# 主观题手写作答、评分与错题系统蓝图

日期：2026-07-29  
状态：已确认的产品与技术基线，尚未完成工程实现  
首要课程：IB Mathematics: Analysis and Approaches SL / HL  
扩展范围：IB其他学科与现有AP FRQ

## 1. 核心结论

现有 Cloudflare Pages + Pages Functions + D1 可以继续使用，不需要重建系统，但当前线上只有 D1 绑定，尚未配置 R2、异步处理队列和手写识别服务。

完整架构为：

```text
Cloudflare Pages 前端
        ↓
Pages Functions 作答接口
        ↓
私有 R2 保存手写图片
        ↓
D1 保存作答、识别、评分和错题数据
        ↓
Cloudflare Queue 调度任务
        ↓
独立处理 Worker 调用识别服务
        ↓
Agnes AI 转录文字、公式和步骤
        ↓
数学检查器与题库评分点共同生成建议结果
        ↓
学生确认后写入正式学习记录
```

R2 使用 Standard storage。原始图片建议保留 30 天；长期保存压缩图、LaTeX、评分点结果和知识点记录。图片保持私有，识别时生成短时访问地址。

## 2. 不可改变的产品原则

1. IB 主观题不能按整题简单记录对错。
2. 作答、得分和错题记录的最小单位是小问及其评分点。
3. 每个评分点必须关联具体知识点。
4. 自动识别只能生成建议，不直接成为正式成绩。
5. 学生确认后，结果才能进入知识点掌握度和错题库。
6. 系统不得根据最终答案推测学生一定写出了中间步骤。
7. 低可信结果必须让学生修正、重新拍照或手动评分。
8. 识别服务必须可替换，不能让产品依赖单一模型。

## 3. 学生完整操作流程

```text
选择知识点和题目
→ 在纸上完成每个小问
→ 按小问拍照
→ 裁剪、旋转、压缩并确认清晰度
→ 上传私有 R2
→ 后台识别文字、LaTeX、图形和步骤
→ 程序检查数值与数学关系
→ 对照题库评分点生成建议得分
→ 显示每个评分点及原图依据
→ 学生确认、修改或重新拍照
→ 生成小问级错题和知识点失分记录
→ 安排重做与对应知识点练习
```

## 4. 题库评分点标准

现有 `parts`、`part_marks` 和整段 `markscheme.rows` 不足以支持步骤级评分。每个小问必须拆成独立评分点。

建议结构：

```json
{
  "id": "b-M1",
  "marks": 1,
  "category": "method",
  "requirement": "使用正确的等差数列求和公式",
  "expected_evidence": [
    "S_n=n/2(2a+(n-1)d)",
    "等价的求和表达式"
  ],
  "knowledge_points": ["AA-1.2.2"],
  "answer_modes": ["formula", "written_step"],
  "depends_on": [],
  "automatic_check": "symbolic_or_semantic",
  "student_feedback": "需要先建立前 n 项和表达式"
}
```

每道公开主观题必须满足：

- 小问评分点分值之和等于小问总分。
- 每个评分点至少关联一个知识点。
- 每个评分点声明所需证据类型。
- 每个评分点声明检查方法。
- 整题主知识点不能代替小问级知识点。

## 5. 手写上传标准

- 每个小问最多 3 张图片。
- 支持 JPEG、PNG、WebP。
- 单张客户端压缩到约 1–3 MB。
- 上传前进行裁剪、旋转、亮度和清晰度检查。
- 尽量只包含当前小问。
- 文件以二进制流上传，不使用 Base64 长期保存。
- D1 只保存图片对象编号和元数据，不保存图片内容。
- 网络中断后可以恢复，不产生重复正式记录。
- 学生可以主动删除自己的原图。

## 6. Agnes AI 的职责

首选模型：`agnes-2.0-flash`，通过 OpenAI 兼容的 `/v1/chat/completions` 接口调用。

Agnes 负责：

- 手写文字转录。
- 数学公式转 LaTeX。
- 识别题号、小问和书写顺序。
- 整理学生实际写出的步骤。
- 提取最终答案。
- 描述图形、表格和坐标图。
- 标记涂改、不确定区域和可信程度。

Agnes 不单独负责：

- 决定正式成绩。
- 完成全部数学等价判断。
- 补写学生没有写出的步骤。
- 直接修改知识点掌握度。
- 直接创建正式错题。

模型层采用统一接口：

```text
RecognitionProvider
 ├─ AgnesProvider
 ├─ 备用视觉模型
 └─ 人工填写模式
```

## 7. 数学检查与评分顺序

1. 图片质量判断。
2. 文字、公式、图形和位置转录。
3. 按原图顺序整理学生步骤。
4. 数学检查：数值代入、方程验证、表达式规范化、微积分关系、误差范围、有效数字、单位和图像特征。
5. 对照当前小问的评分点逐项判断。
6. 返回建议得分、原图依据、缺失步骤、失分知识点和不确定位置。
7. 学生确认后形成正式记录。

学生端必须显示评分点明细，而不是只显示一个总分。例如：

```text
建议得分：2/3

✓ 写出正确的求和公式：1分
✓ 正确建立不等式：1分
✗ 没有正确选择最小正整数：0分

失分知识点：AA-1.2.2
```

学生可以确认、修改识别公式、修改评分点或重新拍照。

## 8. 数据模型

主观题作答不能继续全部存入单个 `progress_snapshots` JSON。建议新增：

- `response_attempts`：一次完整作答。
- `response_parts`：小问状态、得分和确认信息。
- `response_assets`：R2 图片编号及元数据。
- `recognition_runs`：识别任务、模型、版本和状态。
- `recognized_blocks`：文字、公式、图形、图片位置和可信程度。
- `rubric_awards`：逐评分点结果和依据。
- `mistake_entries`：最终确认的知识点失分记录。

统一状态：

```text
draft
→ uploaded
→ queued
→ recognizing
→ needs_confirmation
→ confirmed
→ archived
```

## 9. 错题库标准

错题库最小单位是小问中的失分点。一条记录至少保存：

- 题目与小问。
- 学生确认后的得分和满分。
- 手写答案缩略图。
- 识别出的 LaTeX 和步骤。
- 已获得与未获得的评分点。
- 主要和次要知识点。
- 学生确认的错误原因。
- 系统建议。
- 下次复习时间。
- 后续重做结果。

统一错误原因包括：

- 概念不理解。
- 方法选择错误。
- 公式记忆错误。
- 运算错误。
- 条件遗漏。
- 单位或精度错误。
- 图像表达不完整。
- 推理说明不足。
- 最终答案表达不规范。
- 时间不足。
- 系统识别不准确。

## 10. 知识点复习

知识点掌握度综合以下信息：

- 最近作答表现。
- 评分点完成情况。
- 重做结果。
- 时间衰减。

知识点页面展示练习次数、评分点获得率、常见失分步骤、最近手写答案、待重做题目和推荐练习。不能以单次整题对错代表掌握。

## 11. 跨学科扩展

底层上传、存储、队列、确认、错题和知识点系统保持统一；各学科提供自己的答案类型和检查器。

- 数学、微积分、统计：公式、推导、图像、数值和有效数字。
- 物理：公式、单位、量纲、矢量、受力图、电路图和实验分析。
- 化学：化学方程式、电荷、上下标、结构式、计算和实验现象。
- 生物：关键词、因果链、过程顺序、标注图和数据分析。
- 经济：坐标轴、曲线、移动方向、均衡变化和文字解释。
- 计算机科学：代码、运行过程、变量状态和算法步骤，并优先支持直接输入代码。
- 语言与人文：观点、证据、解释和任务回应。

统一适配结构：

```json
{
  "subject_adapter": "ib-math",
  "supported_answer_modes": [
    "handwriting",
    "formula",
    "graph",
    "diagram",
    "table",
    "typed_text"
  ],
  "validators": [
    "symbolic_math",
    "numeric_tolerance",
    "unit_check",
    "rubric_match"
  ]
}
```

## 12. 管理与质量验证

后台需要支持：

- 查看低可信识别记录。
- 对照原图修改 LaTeX 和评分点。
- 查看学生对系统建议的修改。
- 统计不同题型、符号和学科的识别质量。
- 暂停表现不稳定的自动评分类型。
- 切换识别服务。
- 设置学生图片额度和图片保留时间。
- 查看 R2、队列和模型使用量。

正式开放建议评分前，至少建立 200 份真实手写答案验证集，覆盖不同字迹、照片质量、SL/HL、正确与部分正确答案、分数、根号、指数、积分、矩阵、向量、涂改、多页答案和坐标图。

至少统计：

- 最终答案识别正确率。
- 公式转录正确率。
- 步骤顺序正确率。
- 评分点一致率。
- 不该给分却给分的比例。
- 低可信结果能否被正确标记。

未达到内部标准的题型只能使用辅助识别和学生确认，不能自动生成建议评分。

## 15. 设备、Quiz、Mock Exam 与访问权限补充决策

本节记录 2026-07-29 进一步确认的产品规则。若前文中的通用上传描述与本节冲突，以本节为准。

### 15.1 设备策略

当前继续开发一个响应式 Web 应用，不把原生手机应用作为首期前提。

- 电脑网页支持选择本地图片或 PDF、拖放、多选、排序、旋转和裁剪。
- 手机浏览器支持调用相机和相册，允许连续拍摄多页后统一排序和确认。
- 平板支持相机、相册和文件上传；手写笔直接书写不作为首期条件。
- 移动浏览器必须同时保留“拍照”和“从相册选择”，不能假设不同设备具有完全一致的相机行为。
- 上传过程显示单张状态，并支持短暂离开页面后的恢复。

### 15.2 两套主观题模式

#### 自主核对模式

- 不调用 Agnes，不产生模型处理费用。
- 学生可以在线完成后主动查看答案和评分标准。
- Quiz 和 Mock Exam 都可以下载打印。
- 试卷 PDF 与答案、评分标准 PDF 分开生成。
- 登录用户可以选择手动填写小问得分和错误原因，但不强制。
- 游客不产生需要账号保存的主观题学习记录。

#### 系统辅助评阅模式

- 仅已登录注册用户可使用手写上传。
- 系统负责转录、数学检查、评分点建议和知识点诊断。
- 学生确认后才形成正式学习记录。
- 首期不区分普通注册用户、付费用户和翎英学员。
- 后续可以通过能力授权将其调整为付费或翎英学员专属，不改变上传、R2、D1 和评分数据结构。

### 15.3 Quiz 生命周期

- Quiz 是临时知识点练习。
- 不限制每名学生每天、每个科目的生成次数。
- 不保存生成出来的整套 Quiz 试卷记录。
- 页面刷新或退出后，不承诺恢复同一套未完成 Quiz。
- 已登录学生若选择系统辅助评阅，可以建立短期作答任务；确认后只保存学习结果、评分点和错题，不保存整套 Quiz 档案。
- 游客可以生成允许的 Quiz，但不能使用手写上传和系统辅助评阅。
- 现有 AP MCQ 自动判定和学习记录逻辑不受本规则影响。

### 15.4 Mock Exam 生命周期

Mock Exam 是登录学生的持久化考试档案。

- 每名学生每个科目每天最多生成一套。
- 业务日期默认按 Asia/Shanghai 计算。
- 同一天再次进入时打开已生成的同一套 Mock Exam，不重新抽题。
- 生成时保存有序题目 ID、分值、课程配置标识、题库发布批次和随机种子。
- 学生可以退出后回来继续。
- Mock Exam 保存在个人记录里，支持继续作答、查看结果、复习和重做错题。
- 一套 Mock Exam 可以选择自主核对，也可以完成后选择系统辅助评阅。
- 建议使用 D1 唯一约束 `(user_id, subject_id, generation_business_date)` 保证每日每科只生成一套，但允许不限次数重新打开。

建议状态：

```text
generated
→ in_progress
→ completed
→ upload_draft（可选）
→ queued（选择系统辅助评阅时）
→ needs_confirmation
→ scored
→ reviewed
```

### 15.5 Mock Exam 批量上传

学生应先完成整套 Mock Exam，再进入统一答卷上传中心，不要求做完一个小问就立即上传。

```text
完成整套试卷
→ 一次选择全部照片或 PDF
→ 排序、旋转、裁剪
→ 自动识别页码、题号和小问
→ 学生确认页面映射
→ 整套提交处理
```

- 支持照片和 PDF 批量选择。
- 支持保存上传草稿，学生可以分多次补充页面。
- 标准打印答题册应显示 Mock Exam 编号、科目、题号、小问和页码。
- 每页或每个答题区域可以包含机器可读短编号或二维码，用于对应题目，不包含学生隐私信息。
- 对没有使用标准答题册的自备纸张，系统尝试识别手写题号，并提供手动指定题目和小问的入口。
- 页面映射必须由学生确认后，才按小问创建识别任务。

建议新增数据表：

- `mock_exams`：持久化 Mock Exam 及每日唯一键。
- `mock_exam_items`：不可变的题目 ID、顺序和分值引用。
- `mock_exam_sessions`：继续作答、完成、评分和复习状态。
- `mock_upload_batches`：批量上传草稿。
- `mock_page_mappings`：照片或 PDF 页面与题目、小问的对应关系。

### 15.6 访问权限与未来收费预留

| 用户状态 | Quiz | 持久化 Mock Exam | 手写上传 | 系统辅助评阅 | 自主核对 |
| --- | --- | --- | --- | --- | --- |
| 游客 | 可以使用允许的 Quiz | 不开放本主观题档案 | 不开放 | 不开放 | 可以使用允许的答案流程 |
| 已登录注册用户 | 可以 | 可以 | 可以 | 可以 | 可以 |
| 翎英学员 | 可以 | 可以 | 可以 | 可以 | 可以 |

首期不实施收费。服务端从第一版开始预留统一能力键：

```text
constructed_response_upload
constructed_response_analysis
mock_exam_persistence
```

首期上传和辅助评阅能力对所有已登录注册用户开放。未来调整访问范围时，只修改服务端能力授权规则。权限必须由服务端确认，不能只依赖前端隐藏按钮。

### 15.7 后续学科范围

IB Math AA 稳定后，优先把同一套手写上传、评分点确认和错题逻辑扩展到现有 AP FRQ。AP MCQ 继续使用现有自动判定方式，两者可以共用账号、知识点、历史和错题入口，但不强行采用相同评分方式。

## 16. 返工预防审查与补齐规则

### 16.1 产品定位必须设备无关

正式名称应使用“网页端答卷提交中心”，不能把功能定义成手机拍照功能。所有入口最终提交的是答卷文件，来源可以是：

- 手机或平板相机拍摄的照片。
- 手机、平板或电脑相册中的图片。
- 电脑本地图片。
- 扫描仪生成的图片或 PDF。
- 多页 PDF。
- 后续支持的网页内文字、LaTeX、代码或手写板输入。

R2、D1、识别任务和评分流程只处理统一的 `response_asset`，不依赖设备类型。设备信息只用于诊断上传体验，不参与评分。

### 16.2 PC 与手机跨设备接力

常见流程可能是学生在电脑上生成、查看或下载 Mock Exam，完成纸质答卷后用手机拍摄。因此 Mock Exam 上传中心必须支持：

1. 学生在电脑端打开某一份已保存的 Mock Exam。
2. 选择“在本机上传文件/PDF”或“使用手机继续上传”。
3. 电脑显示一个短时二维码或短码，指向同一 `mock_upload_batch`。
4. 手机完成登录确认后拍照上传。
5. 电脑端自动刷新缩略图、页数和上传状态。
6. 学生可以在任意一端完成排序和页面映射确认。

短时二维码只包含上传会话标识，不包含题目答案、学生姓名或永久访问地址，并应在短时间后失效。

### 16.3 Mock Exam 生成必须由服务端负责

当前项目的 AP Mock Exam 由浏览器随机抽题并主要保存在 `sessionStorage`。该方式不能满足每日唯一、跨设备继续和历史试卷不变的要求。

新 Mock Exam 必须通过服务端原子创建：

- 服务端确认登录状态和科目。
- 服务端计算 Asia/Shanghai 业务日期。
- 服务端先查询当日已有 Mock Exam；存在则直接返回已有记录。
- 不存在时在一次数据库事务中创建试卷、有序题目 ID 列表和每日唯一键。
- 两个浏览器标签页同时请求时也只能产生一套。
- 生成过程中失败的半成品不能占用当天名额。
- 学生归档当日 Mock Exam 后仍不能重新生成另一套，只能重新打开或复习原试卷。

IB Math AA SL 和 HL 作为不同 `subject_id` 分别计算每日额度。

### 16.4 Mock Exam 与作答次数必须分离

“每天每科生成一套”限制的是试卷，不是复习次数。

- `mock_exam` 是不可变试卷档案。
- `mock_attempt` 是学生对该试卷的一次作答。
- 一套试卷至少有一次首次作答，也可以产生后续复习作答。
- 后续复习不能改变第一次作答的答案、用时和成绩。
- 错题重做记录使用 `attempt_kind=review`，不占用新的每日 Mock Exam 名额。

### 16.5 计时必须预留两种模式

为同时满足真实模拟和一次做不完以后继续，数据结构预留：

- `timing_mode=strict`：开始后按绝对时间计算，适合完整模拟。
- `timing_mode=resume`：只累计实际作答时段，适合分段练习。

无论首期界面开放哪一种，数据库都保存开始时间、累计用时、暂停时间、提交时间和计时模式，避免以后改表。

### 16.6 查看答案会改变作答性质

学生选择自主核对并查看答案后，系统记录 `solution_revealed_at`。

- 查看答案后仍可上传答卷并获得学习建议。
- 该结果标记为“已查看答案后的练习结果”，不能与未查看答案的首次模拟结果混在一起。
- 答案 PDF 下载同样记录为已获取答案。
- 试卷 PDF 和答案 PDF 必须分开。

### 16.7 Quiz 虽不保存整套试卷，也要保存必要引用

Quiz 不建立长期试卷档案，但如果学生选择上传并等待处理，系统必须暂时保存：

- 本次题目 ID 和顺序。
- 小问 ID、评分点 ID 和知识点 ID。
- 学生确认前所需的题目内容路径和内容指纹。

使用过的题目内容不允许被原地覆盖，因此处理期间不会读取到另一份内容。任务确认或过期后，可以删除临时组合，只保留最终学习结果及其题目 ID。

### 16.8 题目内容不可覆盖，处理配置必须可追踪

每次系统辅助评阅保存：

- 题目 ID、小问 ID 和评分点 ID。
- 实际应用的知识点 ID。
- 识别提供方和模型名称。
- 提示模板标识。
- 数学检查器发布标识。
- 学生最终确认记录。

使用过的题目或评分点不能原地修改；修正后创建新的题目 ID。历史成绩不自动变化。若需要重新计算，必须新增一条评阅记录，不能覆盖原结果。

### 16.9 批量页面映射不能完全依赖自动识别

必须处理以下情况：

- 一道题有多页答案。
- 一页包含多个小问。
- 附加页没有二维码。
- 学生漏拍、重复拍或拍摄顺序错误。
- PDF 页和照片混合上传。
- 某页属于草稿，不应参与评分。
- 同一页需要裁成两个题目区域。

提交前必须有可视化页面映射确认，支持拖动排序、拆分、合并、排除和手动指定题号。

### 16.10 大型 Mock Exam 上传必须可恢复

- 文件逐个上传，单个失败不影响已成功文件。
- 每个文件使用稳定的客户端上传编号，重新点击不产生重复对象。
- 上传草稿可以跨设备继续。
- 页面显示文件数量、总大小、成功、处理中和需要重传状态。
- 服务端限制单文件大小、总页数、总大小和允许格式。
- 服务端检查真实文件类型并尝试解码，不能只相信文件扩展名。
- PDF 转页面和缩略图生成属于后台任务，不阻塞网页请求。

### 16.11 部分处理失败不能拖垮整份试卷

Mock Exam 的处理单位是页面和小问：

- 一页识别失败时，其他页面继续处理。
- 一个小问需要重传时，不要求重新提交整套答卷。
- 队列任务必须支持重复执行但不重复计费和写入正式结果。
- Agnes 暂时不可用时保留上传记录，稍后继续，或切换到手动核对模式。
- 所有建议分必须等到对应小问处理完成后再进入确认页面。

### 16.12 自主核对也需要完整学习闭环

自主核对不是简单显示答案。已登录学生可以：

- 手动填写每个小问得分。
- 勾选未获得的评分点。
- 选择错误原因。
- 把指定小问加入错题库。
- 安排重做。

游客只能在当前页面核对，不保存个人学习记录。

### 16.13 权限在关键节点分别确认

服务端在以下节点分别确认当前能力：

- 创建上传批次。
- 写入 R2。
- 提交系统辅助评阅。
- 查看私有原图。
- 修改评分确认。

若未来访问范围发生变化，已经合法提交并进入处理的任务可以完成；新的任务按新规则判断。这样不会出现处理中途改变规则导致答卷丢失。

### 16.14 数据保留与学生控制

- 原图、缩略图、识别文本、最终评分采用不同保留周期。
- 删除 Mock Exam 时默认归档，不立即清除学习结果。
- 学生可以单独删除原始图片，同时保留已确认的文字、得分和知识点记录。
- 图片元数据不使用学生姓名作为对象路径。
- 第一次使用外部识别服务前，应明确提示图片将被交给外部服务处理。

### 16.15 成本与用量必须从第一版可控

- 每名用户设置单次页数、每日页数和并发处理数量上限。
- 客户端压缩后再上传。
- 相同文件可以通过内容指纹避免重复处理。
- 低清晰度图片先要求重传，不发送给识别模型。
- Agnes 免费或低价不能作为长期产品假设，费用记录必须按用户、任务、科目和模型版本统计。
- 未来付费只调整能力额度和授权规则，不改变作答模型。

### 16.16 跨学科输入必须在核心模型中预留

`response_asset` 和 `recognized_block` 从第一版支持以下类型：

```text
text
formula
graph
diagram
table
code
chemical_equation
labeled_figure
```

IB Math AA 首期只实现必要类型，但数据库和接口不能只写死为 LaTeX 公式，否则扩展 AP FRQ、物理、化学和生物时需要重建。

### 16.17 首期实现边界

为了控制复杂度，首期可以只交付：

- Web 端电脑文件上传、手机拍照/相册上传和平板上传。
- Quiz 自主核对与登录用户的小问上传。
- Mock Exam 服务端生成、每日唯一、保存、继续和批量上传草稿。
- 手动页面映射作为可靠基础，自动映射作为辅助。
- 学生手动评分和错题闭环。
- Agnes 只做转录，不立即自动确认得分。

但上述数据表、稳定 ID、内容锁定字段、设备无关资产模型、试卷与作答分离、权限键和状态机必须从第一版完整建立。

## 17. 题目定位、统一作答记录、Mock 计时与学习中心

本节记录 2026-07-29 对 Quiz、Mock Exam 和学习历史底层模型的进一步确认。

### 17.1 不为每次生成复制完整题目

每道题只使用一个稳定且全局唯一的 `question_id`。生成 Quiz 或 Mock Exam 时记录有序的 `question_id`，不复制整份题目 JSON，也不额外引入题目版本 ID。

推荐结构：

```json
{
  "question_id": "lynkedu_math_aa_sl_000123",
  "content_hash": "345cd53613915973...",
  "status": "active",
  "first_used_at": "2026-07-29T10:00:00Z",
  "content_locked_at": "2026-07-29T10:00:00Z",
  "replaces_question_id": null
}
```

规则：

- 草稿题在第一次被学生实际使用前可以修改。
- 第一次进入学生 Quiz、Mock 或作答记录后，影响作答和评分的内容立即锁定。
- 锁定后不得覆盖题干、选项、图片、表格、小问、答案、分值或评分点。
- 需要修正时创建新的 `question_id`，并通过 `replaces_question_id` 指向旧题。
- 旧题改为 `retired`，不进入新练习，但继续服务历史记录。
- `content_hash` 用于检查已锁定内容是否发生意外变化，它不是题目版本号。

Mock Exam 只需要保存：

```text
mock_exam_id
subject_id
generation_business_date
ordered question_id list
section and order
paper and timing configuration
generation_rule_id
```

这样既避免大量重复数据，也能保证历史试卷永久还原。真正的硬要求是“使用过的题目不可覆盖”，而不是维护显式版本号。

### 17.2 统一的学习会话和作答模型

Quiz、Mock Exam、错题重做和相似题练习统一使用：

```text
learning_session
  └─ question_attempt
       ├─ response
       ├─ response_asset
       ├─ grading_result
       └─ knowledge_result
```

建议数据表：

- `learning_sessions`：一次 Quiz、Mock、错题重做或复习会话。
- `question_attempts`：学生对某个题目 ID 的一次实际作答。
- `attempt_responses`：MCQ 选项、文字、公式或结构化答案。
- `response_assets`：图片或 PDF 等答卷文件。
- `grading_results`：自动判定、手动评分或系统辅助评阅结果。
- `attempt_knowledge_results`：该次作答对具体知识点的表现。

`learning_sessions.session_type` 至少支持：

```text
quiz
mock
mistake_review
similar_practice
manual_practice
```

### 17.3 每次实际作答都要保留

只要登录学生产生了实际答案，就创建 `question_attempt`：

- MCQ 提交了一个选项。
- 简答题上传了图片或 PDF。
- 简答题输入了文字、公式或代码。
- 自主核对后手动填写了得分或评分点。
- 对历史错题再次作答。

每次重做都新增记录，不覆盖过去记录。学习中心可以分别显示第一次、最近一次和最好一次表现。

对于 MCQ，记录学生正式提交或被系统锁定的答案，不记录尚未提交的临时切换。对于简答题，草稿上传、正式提交、系统建议和学生确认是同一次 `question_attempt` 的不同状态。

### 17.4 Quiz 不保存试卷，但保存已发生的学习

Quiz 生成时不立即建立长期试卷档案。

- 仅生成题目顺序并在当前网页会话使用。
- 学生未作答的题目不需要写入长期学习记录。
- 登录学生第一次提交答案或开始上传时，建立轻量 `learning_session`。
- 每完成一道题，就追加对应的 `question_attempt` 和 `question_id`。
- 学生退出后，已完成题目的记录保留；尚未完成的整套 Quiz 不提供恢复。
- 简答题上传处理中，即使原 Quiz 页面已关闭，也能从学习中心的“待处理/待确认”入口继续。
- 游客的 Quiz 不写入账号学习记录。

因此“不保存整套 Quiz”和“保存每次做题情况”并不冲突：前者不保存未完成的随机题目组合，后者保存已经发生的答案与结果。

### 17.5 Mock Exam 保存试卷，也保存每一道实际作答

Mock Exam 由两个层次组成：

```text
mock_exam     = 当天生成的固定有序题目 ID 列表
mock_attempt  = 学生对这套 Mock 的某一次作答过程
```

Mock Exam 中所有题目顺序保存在 `mock_exam_items`；学生真正回答后，再为对应题目创建 `question_attempt`。未答题也可以通过 Mock 完成状态统计，但不能伪造一条有答案的题目记录。

### 17.6 Mock Exam 计时规则

不再区分复杂计时模式。所有 Mock Exam 进入后都计时，并支持退出后按剩余时间继续。

建议字段：

```text
time_limit_seconds
remaining_seconds
timer_status
last_timer_saved_at
active_timer_lease
```

规则：

1. 学生点击进入或继续 Mock 时，计时开始。
2. 页面每 10–15 秒保存一次剩余时间。
3. 切换题目、切换区段、页面进入后台和正常退出时立即保存。
4. 浏览器意外关闭时，以最近一次保存值恢复，最多存在一个保存周期的误差。
5. 下次进入时从服务端保存的 `remaining_seconds` 继续。
6. 剩余时间到 0 时自动提交当前已保存答案。
7. 同一 Mock 同一时间只允许一个有效计时会话；换设备继续时，新的计时会话替代旧的计时会话。

服务端是最终时间记录来源，浏览器本地时间只负责显示和短暂离线缓冲。

### 17.7 生成前资格判定

进入 Mock Exam 页面时，先调用服务端资格接口，例如：

```text
GET /api/mock-exams/eligibility?subject_id=ib-math-aa-sl
```

返回：

```json
{
  "can_generate": false,
  "business_date": "2026-07-29",
  "existing_mock_exam_id": "mock_...",
  "existing_status": "in_progress",
  "next_available_at": "2026-07-30T00:00:00+08:00"
}
```

页面规则：

- 可以生成：显示“生成今日 Mock Exam”。
- 当日已经生成：不再显示生成按钮，显示“继续今日 Mock Exam”或“前往学习中心查看”。
- 已经完成：显示“查看结果”和“前往学习中心复习”。
- 前端提前查询用于体验，真正创建时服务端仍再次确认。
- 并发请求只能返回同一份当日 Mock Exam。

### 17.8 删除不能重置每日额度

学习中心允许学生删除 Mock Exam，但“删除”默认是从个人列表隐藏或移入最近删除，不清除每日生成台账。

- 删除当天 Mock 后，不能再次生成另一套当天试卷。
- 最近删除可以在一定期限内恢复。
- 永久清除图片和个人作答数据时，仍保留最小的每日生成台账，避免同一天重新生成。
- 题目 ID 和公共题库数据不随学生删除行为变化。

### 17.9 学习中心信息架构

建议新增统一 `/learning-center`，不要让 Mock、历史记录、待确认答卷和错题散落在多个没有关联的页面。

学习中心至少包含：

#### 继续学习

- 未完成的 Mock Exam。
- 正在上传或处理的答卷。
- 等待学生确认的评分结果。
- 已安排的错题重做。

#### Mock Exam

按课程和时间存放，每张卡片显示：

- 课程与级别。
- 系统日期和学生自定义名称。
- 创建时间与最后学习时间。
- 当前状态和完成进度。
- 剩余时间。
- 已回答题数和总题数。
- 成绩或待确认状态。
- 继续、上传答卷、查看结果、复习、重命名、删除等操作。

学生重命名只修改 `user_title`，不修改科目、日期、系统编号和题目内容。

#### 做题记录

展示所有已登录状态下产生过答案的题目记录，包括：

- 题目 ID 和当时锁定的题目内容。
- Quiz、Mock 或复习来源。
- 作答时间。
- 学生答案。
- MCQ 对错或简答题得分。
- 对应知识点。
- 是否进入错题库。
- 第一次、最近一次和最好一次表现。

支持按课程、知识点、日期、题型、结果、来源和状态筛选。

#### 错题与复习

- 当前待复习小问。
- 历史重做次数。
- 最近一次表现。
- 推荐下一次复习时间。

### 17.10 学习记录的更新规则

- 每次 `question_attempt` 都永久作为一次独立历史事件保存，除非学生明确清除个人记录。
- 错题库可以根据最新结果改变当前状态，但不能删除过去的作答历史。
- 知识点掌握度由多次作答计算，不能覆盖成单一最新结果。
- Mock 的第一次成绩、最近成绩和复习成绩分开显示。
- Quiz 中同一道题多次出现时，每次提交都新增一条作答记录。

### 17.11 还需提前固定的边界

1. `question_id` 一经学生实际使用不得改变；修题只能创建新题目 ID。
2. 题目引用的图片、表格、小问和评分点也必须锁定并可长期还原。
3. 当题目停止用于新练习时，历史记录仍能显示当时内容。
4. Mock 生成算法必须记录稳定的规则标识，保证可以解释当时为何选择这些题。
5. 题库不足时不能生成残缺 Mock；资格接口应提前返回不可生成原因。
6. 生成成功后才占用当日名额；数据库半成品不占名额。
7. 已经查看答案的作答继续保留，但明确标记为已查看答案后的练习。
8. 主观题图片上传后即形成草稿作答；未完成处理的任务在学习中心可见。
9. 未来从普通注册开放改为付费或翎英学员专属时，不改变已完成历史记录的查看权。
10. 现有 AP MCQ、Quiz 历史和 Mock 历史最终需要迁移或适配到统一 `question_attempt` 模型，避免长期维护两套互不一致的学习记录。

## 18. 未来可选的长期增强项（首期不实施）

本节记录长期可能需要的增强项，不属于首期完成条件，不得用来扩大当前开发范围。首期实际底层以第 19 节为准。

### 18.1 ID 不能包含会变化的业务含义

新题目 ID 不应依赖知识点、章节、Paper、年份、题号或难度，因为这些分类以后可能修正。

推荐使用不透明 ID，例如：

```text
q_01K2M7Y8R4F6A9C3
```

现有带课程和主题文字的旧 ID 可以保留，但以后不得因为重新分类而改 ID。数据库对 `question_id` 设置全局唯一约束，构建检查同时检查所有课程是否重复。

### 18.2 题目子元素也必须拥有稳定 ID

主观题和组合题不能只保存整题 ID，还需要：

```text
part_id
option_id
mark_point_id
asset_id
stimulus_id
```

- `part_id` 对应小问。
- `option_id` 对应 MCQ 选项，学生答案保存选项 ID，不保存 A/B/C/D 字母。
- `mark_point_id` 对应具体得分点。
- `asset_id` 对应图片、表格或 PDF 资源。
- `stimulus_id` 对应多道题共享的材料。

显示顺序可以变化，ID 不能变化。

### 18.3 首次使用前可编辑，首次使用后自动锁定

题目状态至少包括：

```text
draft
active
retired
withdrawn
```

- `draft` 可以编辑，不进入学生练习。
- 第一次进入学生练习或作答记录时，写入 `first_used_at` 和 `content_locked_at`。
- 锁定后服务端拒绝覆盖评分相关内容。
- `retired` 不再进入新练习，但历史可读。
- `withdrawn` 用于因内容使用范围等原因不能继续完整展示的情况，历史保留最小记录和结果说明。

### 18.4 内容指纹是强制检查，不是版本系统

每道锁定题保存 `content_hash`，由以下评分相关内容计算：

- 题干和共享材料。
- 选项。
- 小问。
- 图片和表格资源 ID。
- 正确答案。
- 分值和评分点。

构建和发布时重新计算。如果同一锁定 ID 的内容指纹变化，发布直接失败，要求创建新题目 ID。

### 18.5 图片和共享材料不能被原路径覆盖

即使题目 JSON 没变，如果同一路径的图片被替换，历史题目仍会改变。因此：

- 锁定题引用的资源采用唯一 `asset_id` 和带内容指纹的文件名。
- 已被锁定题引用的资源不得覆盖。
- 修改图、表、代码块或共享材料时创建新的资源 ID 和新的题目 ID。
- 共享材料停止用于新题后仍需保留，直到没有历史记录引用。

### 18.6 修订关系不能形成混乱链条

新题可以使用 `replaces_question_id` 指向被替代题目，但必须检查：

- 不能指向自己。
- 不能形成循环关系。
- 同一旧题默认只有一个当前正式替代题。
- 新旧题属于兼容课程范围。
- 替代关系不自动迁移学生过去的答案和得分。

### 18.7 分类信息与历史成绩分开处理

知识点分类可能被纠正，但不应迫使题面生成新 ID。采用以下规则：

- 题目的当前分类可以维护更新。
- 每次 `question_attempt` 保存当次实际用于评分和统计的知识点 ID。
- 分类纠正后，新作答使用新分类。
- 是否重新计算历史知识点统计必须通过明确的数据修正任务完成，不能静默改变历史结果。

题干、答案和评分点变化必须创建新题目 ID；仅分类修正不创建新题目 ID。

### 18.8 题库内容和服务端目录必须有一个发布事实源

当前题目主要位于 Pages 静态 JSON，而 Mock 每日限制与历史记录将位于 D1。为避免前端与服务端看到不同题库，每次发布生成统一 `question_registry`：

```text
question_id
subject_id
status
content_hash
content_path
part_ids
mark_point_ids
asset_ids
release_id
```

发布流程先验证目录，再同步服务端题目索引，最后开放新题。Mock 服务端只能从已同步且状态为 active 的目录中选题。

### 18.9 不能直接清除被历史记录引用的题目

数据库和发布检查必须阻止清除以下对象：

- 被 Mock Exam 引用的题目。
- 被学生作答记录引用的题目。
- 被错题库或复习计划引用的题目。
- 被评分记录引用的评分点。
- 被历史题目引用的图片和共享材料。

学生删除自己的作答，不代表公共题目可以被清除。

### 18.10 MCQ 答案不能只保存选项字母

如果以后调整显示顺序，字母可能变化。MCQ 作答保存稳定 `option_id`，页面按当前试卷中的顺序显示 A/B/C/D。评分根据 `option_id` 判断，不根据字母判断。

### 18.11 重复作答不能使用覆盖写入

`question_attempt` 使用独立 `attempt_id`。禁止以 `(user_id, question_id)` 作为唯一键进行覆盖，否则学生重做会丢失第一次记录。

允许建立辅助索引快速查询：

```text
(user_id, question_id, submitted_at)
(learning_session_id, question_id, attempt_number)
```

### 18.12 Mock 题目列表必须防止重复和顺序漂移

- `mock_exam_items` 保存固定 `order_index` 和 `section_id`。
- 同一 Mock 默认不允许重复 `question_id`。
- 生成后不能重新排序或重新抽题。
- 重新打开、下载 PDF、上传答卷和查看结果都读取同一列表。
- 题库中题目后来变为 retired，不影响已经生成的 Mock。

### 18.13 Quiz 作答必须能独立于原页面完成处理

简答题上传后，处理任务直接引用 `attempt_id + question_id + part_id`，不能依赖浏览器仍保留 Quiz 数组。这样学生关闭页面后，任务仍可完成并进入学习中心。

### 18.14 旧题 ID 和旧学习记录需要迁移台账

现有题库已有大量题目 ID。迁移时：

- 保留所有已使用的旧 ID。
- 检测跨课程重复 ID。
- 对缺少小问、选项或评分点 ID 的题目补稳定子 ID。
- 为现有题计算初始 `content_hash`。
- 建立旧本地记录到新 `question_attempt` 的转换规则。
- 无法可靠定位题目的旧记录保留为 legacy，不伪造映射。

### 18.15 必须增加自动检查门

每次题库发布至少检查：

- 全局题目 ID 是否唯一。
- 小问、选项、评分点和资源 ID 是否唯一且完整。
- 锁定题内容指纹是否变化。
- retired 题是否仍被新 Quiz 或 Mock 抽取。
- 新题是否错误复用旧 ID。
- 替代关系是否形成循环。
- 引用的图片、共享材料和评分点是否存在。
- Mock 中是否出现重复题目或不可用题目。

### 18.16 推荐的最小字段

```text
question_id
subject_id
status
content_hash
content_path
first_used_at
content_locked_at
replaces_question_id
created_at
retired_at
```

这套字段已经足够保证“Mock 和 Quiz 只保存题目 ID”长期可靠，不需要额外引入题目版本 ID。

## 19. 最小必要底层（最终执行基线）

首期只执行以下规则：

1. 每道题在所属科目内有唯一 `question_id`；系统定位使用 `(subject_id, question_id)`。
2. Mock Exam 保存有顺序的题目 ID，不复制完整题目内容。
3. Quiz 不保存整套随机题目，只保存学生真正回答过的题目记录。
4. 每次实际作答都新增一条记录，不覆盖过去记录。
5. 简答题图片通过 `question_id + part_label` 对应具体小问。
6. 题目发生影响答案或评分的明显修改时，创建新的题目 ID；普通分类和展示调整不建立复杂版本体系。
7. 已用于学生历史的旧题不从题库文件中直接移除，只标记为不再进入新练习。

首期最小数据表：

### `mock_exams`

保存学生、科目、日期、名称、状态、剩余时间和创建时间。

### `mock_exam_questions`

保存 `mock_exam_id + subject_id + question_id + section + order_index`。

### `question_attempts`

保存：

```text
attempt_id
user_id
subject_id
question_id
part_label（可空）
source_type（quiz/mock/review）
source_id（可空）
answer_json
score
max_score
status
created_at
```

### `attempt_assets`

保存简答题图片或 PDF 的 R2 对象编号，并关联 `attempt_id`。

不在首期实施：

- 显式题目版本系统。
- 复杂替代关系链。
- 独立的小问、选项、资源全局 ID 体系。
- 题目内容指纹锁定流程。
- 静态题库与 D1 的复杂双向同步。
- 大规模旧数据迁移。

这些内容只有在真实使用出现明确需要时再增加。当前目标是用最少的数据结构正确支持：每日 Mock、断点计时、Quiz/Mock 作答记录、手写上传、学习中心和错题复习。

## 20. 最终题目编号方案

### 20.1 当前题库实测

2026-07-29 对当前 34 个正式题库文件进行检查：

- 共 5,627 道题。
- 缺少题目 ID：0。
- 同一科目内部重复 ID：0。
- 不同科目之间重复的 ID 值：659 种。
- 现有 ID 均只使用可安全存储的英文字母、数字、点、下划线、冒号或连字符。

因此现有 `question_id` 适合作为科目内部编号，但不能脱离科目单独定位题目。

### 20.2 唯一定位

数据库保存两个独立字段：

```text
subject_id
question_id
```

唯一约束：

```text
UNIQUE(subject_id, question_id)
```

需要在日志或接口中表示一个完整定位时，可以显示为：

```text
ap-biology::2008_FRQ1
ap-statistics::2008_FRQ1
ib-math-aa-sl::lynkedu_math_aa_sl_t1_p1_01
```

不新增另一套数据库题目 ID，也不要求重新编号现有 5,627 道题。

### 20.3 新题编号格式

以后新增的题目，在每个科目内部按照稳定的题型或 Paper 前缀分别编号：

```text
AP:
MCQ-000001
FRQ-000001

IB:
P1-000001
P2-000001
P3-000001
```

- AP 的 `MCQ` 和 `FRQ` 对应不同作答与评分形式。
- IB 的 `P1`、`P2`、`P3` 对应试卷类型、计算器规则和题目形式。
- 数字为六位流水号，在同一科目和同一前缀内递增。

编号中不写题目来源、知识点、章节、难度、年份或当前显示题号。来源保存在 `source`，更详细的题型与 Paper 信息仍保存在题目字段中。

流水号只增加，不因题目停用而重复使用。

现有题可以保留原 ID，不强制改名；以后新增 AP 题采用 `MCQ/FRQ-六位流水号`，新增 IB 题采用 `P1/P2/P3-六位流水号`。所有题都依赖 `(subject_id, question_id)` 唯一定位。

### 20.4 小问定位

首期不单独建立复杂小问 ID。使用：

```text
subject_id + question_id + part_label
```

例如：

```text
ib-math-aa-sl::P1-000061::b
```

没有小问的题，`part_label` 为空。

### 20.5 必要检查

每次题库验证只新增四项简单检查：

1. `subject_id` 和 `question_id` 都不能为空。
2. 同一科目内 `question_id` 不能重复。
3. ID 只能使用英文字母、数字、点、下划线和连字符。
4. 已经用于学生记录的题目 ID 不允许改名或重复分配。

这套方案不需要全量重编号，不需要题目版本系统，也足以支持 Mock、Quiz、学习中心、错题和手写上传。
